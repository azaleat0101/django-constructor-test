# Конструктор тестов

Консольное приложение для создания и прохождения тестов с веб-интерфейсом
на Django. Разрабатывается поэтапно: от консольного скрипта к полноценному
веб-приложению.

## Назначение

Приложение позволяет создавать тесты с вопросами и вариантами ответов,
проходить их и получать автоматическую оценку по проценту правильных
ответов. Консольная версия даёт полный набор операций (создание,
редактирование, удаление тестов и вопросов), веб-версия на текущем
этапе предоставляет просмотр данных.

## Целевая аудитория

- Преподаватели и методисты, которым нужно быстро собирать тесты.
- Студенты и учащиеся, проходящие проверочные задания.
- HR-специалисты, проводящие первичное тестирование кандидатов.

## Предметная область

Система тестирования знаний. Основные сущности:

- **Test** — тест (название, описание, вопросы);
- **Question** — вопрос (текст, варианты ответов, правильный ответ);
- **User** — пользователь (имя);
- **Attempt** — попытка прохождения (пользователь, тест, результат, дата).

Пользователь проходит тест, отвечая на вопросы. Программа проверяет
ответы, считает процент правильных и выставляет оценку.

## Классы предметной области (ПР3)

### `Question` — вопрос теста
- `text` — текст вопроса;
- `options` — список вариантов ответа;
- `correct_answer` — правильный вариант.

Методы: `check_answer()`, `update()`, `to_data()`, `from_data()`, `__str__()`.

### `Test` — тест
- `id`, `title`, `description`;
- `questions` — список объектов `Question`.

Методы: `add_question()`, `update()`, `questions_count` (свойство),
`validate_title()` (статический), `__str__()`.

### `User` — пользователь
- `id`, `name`.

### `Attempt` — попытка прохождения
- `id`, `test: Test`, `user: User`, `correct`, `total`;
- `percent`, `grade` (свойство), `date`.

## Веб-интерфейс (ПР5–ПР6)

### Реализованные страницы

| URL | View-функция | Назначение |
|---|---|---|
| `/` | `homepage.views.index` | главная страница |
| `/quizzes/` | `quizzes.views.quizzes` | список тестов |
| `/quizzes/<int:test_id>/` | `quizzes.views.quiz_detail` | тест с вопросами |
| `/attempts/` | `attempts.views.attempts` | список попыток |
| `/attempts/<int:attempt_id>/` | `attempts.views.attempt_detail` | одна попытка |

При несуществующем идентификаторе возвращается страница с сообщением
об ошибке и HTTP-статусом 404.

### Маршрутизация

Двухуровневая:
- `constructor/urls.py` — подключает маршруты приложений через `include()`;
- `urls.py` каждого приложения — содержит конкретные адреса.

Для динамических адресов используются конвертеры `<int:test_id>`
и `<int:attempt_id>`.

В каждом `urls.py` задан `app_name`, что позволяет использовать
пространства имён: `homepage:index`, `quizzes:list`, `quizzes:detail`,
`attempts:list`, `attempts:detail`.

## Хранение данных

На текущем этапе данные хранятся в JSON-файлах:

- Python 3.10+
- Django 5.2 — веб-фреймворк
- Django Template Language (DTL)
- HTML5, CSS3
- Bootstrap 5.3 (CDN)
- JavaScript (вывод текущего года в подвал)
- JSON — хранение данных
- pytest — автоматизированные тесты
- flake8 — проверка качества кода
- Git

Загрузка выполняется функциями storage.py: load_tests(),
load_users(), load_attempts(). Объекты создаются через
from_data() классов предметной области.

Django ORM и база данных на текущем этапе не используются.
